# 工具箱开关：能自己好的失败改成后台自动重试（2026-10-03）

需求（哥哥）：会话标题栏那个「工具箱」按钮**经常显示成「重试」**，但实际上接口是通的，
再点一下就好 —— 需要自动化，别让它看起来像坏了。

## 判断依据（先说清楚我知道什么、不知道什么）

- 现象：chip 渲染出来是 `工具箱 · 重试`（就是 `error` 态），手动点一下就恢复正常。
  「点一下就好」说明**载荷这条路是通的**，失败的只是那一次请求的时机。
- 宿主那条 GET（`src/route.js`）在**会话还不活**时如实回 404「会话不在运行中」——
  它刻意不猜、不兜底。而 chip 是跟着界面挂上去的，**可能比宿主侧的 agent 早一步**。
- 我没有亲眼看到那次失败的错误文本（它在按钮的 `title` 里）。所以这次的改法是按
  **失败的性质**分类，而不是按某一个具体状态码：会自己好的就自己重试，不会的才交给用户。
  要是 hover 看到的文本不属于下面这几类，把它发我。

## 改了什么

| 文件 | 改动 |
|---|---|
| `src/client.js` | 新增 `AUTO_RETRY_DELAYS` 与 `retryableStatus()`；`GatewayChip` 的 `load` 改成"失败后自己按退避再问"；新增 `pending` 态与 `reading` / `hintReading` 两条文案；loading 态圆点加脉动；`apply.retryPolicy` 作为测试出口 |

## 契约：什么会自己重试

```
AUTO_RETRY_DELAYS = [400, 1000, 2000, 4000, 8000]   // 毫秒，共 5 次，约 15 秒
retryableStatus(status) = status === 0 || status === 404 || status >= 500
```

- `0` —— 请求根本没发出去（宿主正在重启、断网）
- `404` —— 这个会话还没挂到宿主上（chip 比 agent 先出现）
- `5xx` —— 宿主或它依赖的服务一时不可用

这三类**都会自己好**，所以后台重试，界面上只显示「工具箱 · 读取中」（灰点脉动），
**不出现错误态**。退避走完还没成功，才落成 `工具箱 · 重试`，把错误原文放进 `title`。

401 / 403（身份）与 400（请求本身写错）**不重试**：再问一百次都是同一个答案，
自动重试只会把一个本来很清楚的错误拖成一段没意义的等待。

手动点一下仍然是"重试读取"，并且**从退避表头开始走**；点之前会先撤掉上一轮还挂着的定时器，
不会两轮叠着发请求。
